나의 공간

집/공방/마을 배치, 회전, 이동, 회수, 부품 색칠과 저장 복원.

생성된 동작

LLM이 만든 함수와 이벤트를 서버가 검증하고, 게임의 부품에 연결.

직접 확인할 순서
  1. 공방 보관함에서 정적 상자와 열리는 상자를 선택합니다.
  2. ‘사용’으로 뚜껑을 움직이고 전체 또는 부품 색상을 바꿉니다.
  3. ‘내 집’에서 바닥에 배치합니다. R 회전, Esc 취소입니다.
  4. 집을 나갔다가 다시 들어와 위치와 색이 유지되는지 확인합니다.
  5. 마을 돌문에서 생존 지역과 난이도를 선택합니다. WASD 이동, E 채집, Q 음식, F 모닥불입니다.
완료되지 않은 범위

공개 HTTPS 서비스·운영 DB 이전, 실시간 멀티플레이, 장편 스토리와 전용 지형, UV 브러시 칠하기, 임의 생물의 얼굴/관절 자동 리깅, 생성물의 완전한 의미·시각 검수는 남아 있습니다. 연속 장식 애니메이션의 시간은 클라이언트에서 진행되므로 서버가 모든 프레임을 시뮬레이션하는 구조는 아닙니다.

플레이어 생성에는 Blender가 들어가지 않습니다.

각 단계를 누르면 무엇을 만들고, 누가 검사하는지 볼 수 있습니다.

동적인 부분

LLM은 부품 이름·계층·위치·회전축과 새로운 함수 이름/인수/계산/이벤트를 만듭니다. 예를 들어 set_open(x)을 생성하고 뚜껑의 동작에 연결할 수 있습니다.

미리 정한 실행 범위

엔진의 회전·수직 이동·빛·색 제어는 고정된 안전한 연산입니다. 생성된 함수는 이 연산들을 조합합니다. 생성 코드에서 파일, 네트워크, 돈, 소유권이나 운영 DB를 조작할 수 없습니다.

개발자 에셋은 별도 경로

컨셉 이미지 → Tripo/개발자 모델링 → Blender의 리깅·애니메이션·환경 아트 → Godot 빌드. Explorer B와 집은 이 경로의 일반 에셋이고, 플레이어 보상으로 생성한 가구는 소유권을 가진 서버 자산입니다.

게임의 최종 견적

텍스트 생성 비교와 H3 이미지 보정 1부품 경로는 실측했습니다. 다른 조합은 공개 요금 기반 예상입니다. 실패·재시도·LLM·호스팅 비용은 별도이며, 이는 현금 결제 내역이 아닙니다.

기본 환산: 예상 Tripo 1크레딧당 1별씨, 최소 설계 예약금 20/40별씨 + 동적 10별씨. 서버 설정으로 조정할 수 있으며 최종 견적 확인 전에는 유료 생성을 시작하지 않습니다.

작은 가구 과제를 실제 모델로 실행했습니다.

상자·꽃 조명·시계에 대해 문법·실행과 요청 동작을 따로 검사합니다. 높은 effort가 항상 좋은 결과를 보장하지는 않습니다. 각 설정 3과제의 소규모 비교이며 부품명 휴리스틱의 한계가 있습니다.

전부 로컬 CLI에서 실행한 Codex 구독 실험입니다. 모델 추론은 원격 서비스에서 처리되며 PC에 모델 가중치를 설치한 것은 아닙니다. API 환산액은 CLI의 맥락 토큰까지 포함한 참고치이고, 실제 GPT API 결제액은 0입니다. v1은 계약 설명에 누락이 있어 v2와 같은 조건으로 합치지 않습니다.

## 0.9.1 기준본 · 2026-10-02 (이전 단계)

개발 계획 1단계인 **현재 수정본 검증·기준본 저장**을 마쳤습니다. 카메라는 주시점을 보간하고 고정 오프셋으로 따라가므로 이동 시작·방향 전환·정지에도 각도가 유지됩니다. 해루는 제공받은 컨셉을 바탕으로 만든 새 3D 메시와 41개 뼈대, Blender에서 직접 제작한 대기·걷기·낚시·인사 동작을 사용합니다. 기존 Explorer B hand-v4 주인공은 유지했습니다. 집·공방의 목재 실내, 출발 아치, 낚싯대·보트와 NPC 소품을 추가하고 가구 배치의 미리보기·회전·취소·부품 색칠을 다듬었습니다. [기준본의 실행·검증·제한 사항](docs/BASELINE_091.md)에 재현 방법과 실제 캡처를 정리했습니다.

`powershell -ExecutionPolicy Bypass -File .\tools\build_game.ps1`는 두 실행본을 만듭니다. `builds/windows/Tripothon.exe`는 **플레이어용**으로 온라인 데모 서버에 연결하고 공방의 만들기·보관함만 표시합니다. 초대 코드는 로그인 화면에서 입력할 수 있습니다. `builds/windows/Tripothon_Developer.exe`는 **개발용**으로 기본 로컬 서버에 연결하며 F3 진단 정보, 생성 방식·모델·코드·부품 맞춤·기록을 표시합니다. 두 실행본 모두 별도의 서버가 필요합니다. API 키와 DB는 실행본에 넣지 않습니다. 온라인 데모의 유료 생성은 서버에서 꺼져 있으므로 플레이어 화면의 공방 사용 가능 여부도 서버 정책을 따릅니다. 로컬 유료 생성은 개발용 [Play_Tripo.cmd](Play_Tripo.cmd)에서만 서버 전용 키를 사용합니다.

편집 가능한 Blender 원본은 `art/source/`, 공개 게임 GLB는 `game/assets/`에 있습니다. 해루 제작에는 Tripo P2 이미지→3D **120크레딧**, 리깅 **25크레딧**, 합계 **145크레딧**을 사용했습니다. 리깅 후 색과 동작을 보완한 `haeru_v1.glb`를 빌드에 포함합니다. [아트 명세](art/haeru-manifest.json)에 출처와 동작 길이를 기록했습니다. 이번 기준본 검증의 추가 유료 호출은 **0회**입니다. 플레이어 런타임 생성 경로에는 Blender를 사용하지 않습니다.

`tools/package_baseline.py`는 두 클라이언트와 무과금 로컬 데모 서버를 버전별 새 폴더로 묶습니다. 현재 실행 폴더는 `builds/Tripothon_Baseline_091`, ZIP은 `artifacts/Tripothon_Baseline_0.9.1_Windows.zip`입니다. Git에는 실행 파일·개인 DB를 넣지 않으며 소스·공용 아트·검증 자료만 저장합니다.

## GitHub 소스에서 실행

이 저장소에는 Godot 게임 소스와 공용 아트, FastAPI 서버 소스가 들어 있습니다. 실행 파일, Python 가상환경, API 키, 플레이어 DB와 개인 생성물은 포함하지 않습니다. Windows에서 Python 3.13, `uv`, Godot 4.7.2를 준비한 뒤 다음을 실행하세요.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup.ps1
powershell -ExecutionPolicy Bypass -File .\tools\run_server.ps1
```

서버는 로컬 `127.0.0.1:8765`에 샘플 모드로 뜹니다. 별도 창에서 Godot 4.7.2로 `game/project.godot`을 열고 실행하세요. 이 PC의 [Play_Tripo.cmd](Play_Tripo.cmd)는 실행 전에 `tools/build_game.ps1`로 개발용 실행본을 만들어야 하며 준비된 로컬 도구와 서버 전용 키 파일을 사용하는 개발용 실행기입니다. 새로 복제한 저장소에서 바로 실행할 수 있는 배포 파일은 아닙니다.

Godot 4.7.2 + Python/FastAPI 기반 3D 게임 프로토타입입니다. 현재 개발 중심은 **맵·캐릭터·7일 생존·Tripo API 연동**입니다. 기본 실행은 **API 비용이 없는 로컬 샘플 서버**입니다. 거래는 후속 개발로 미루고 게임의 장터·판매 진입점을 숨겼습니다. 기존 서버 거래 코드와 데이터는 보존하며, 서버 거래 API 자체를 차단한 변경은 아닙니다.

## 온라인 심사용 데모 · 2026-10-02

Google Cloud 무료 체험 VM에 HTTPS 서버를 배포했습니다. 현재 주소는 [34-28-65-113.sslip.io](https://34-28-65-113.sslip.io/health)이며, `/health`는 `live`·프로토콜 6을 반환합니다. 플레이어 빌드는 이 주소에 기본 연결됩니다. 개발 빌드의 **연결 설정**에서 다른 HTTPS 주소를 입력할 수 있습니다. 신규 가입에는 서버에만 보관하는 초대 코드가 필요합니다. 플레이어별 계정·별씨·소유 가구·7일 생존 기록은 서버의 비공개 SQLite 볼륨에 저장하며, API 컨테이너를 재시작한 뒤에도 남는 것을 점검했습니다. 온라인 데모의 유료 LLM/Tripo 호출은 꺼져 있습니다. 로컬 샘플 모드의 시작 재화와 생성 동작을 온라인 유료 생성으로 오해하지 않도록 구분합니다.

서버 설치·방화벽·비밀 파일·백업·무료 체험 과금 제한은 [온라인 서버 운영 문서](ops/README.md)를 따릅니다. 서버 단위 테스트는 `python -m pytest server/tests -q`, 실제 게임 흐름은 `tools/test.ps1 -Capture`로 검사합니다. Godot에서 온라인 HTTPS 연결을 별도로 확인하려면 `game/tests/remote_health.gd`를 `--base-url=https://서버주소`와 함께 실행합니다. 이 검사는 인증 없이 읽기 전용 상태와 프로토콜만 확인하므로, 실제 온라인 계정 플레이는 별도로 검증해야 합니다.

이 PC에서 실제 Tripo 가구를 게임 중 만들려면 [Play_Tripo.cmd](Play_Tripo.cmd)를 실행합니다. 데스크톱의 `tripo_key.txt`를 **서버만** 읽고, 기존 데모 저장소를 백업한 뒤 로컬 FastAPI 서버와 게임을 켭니다. 마을에서 집이나 공방에 들어가 **만들기 → 프롬프트와 선택적 PNG/JPEG 그림 → 메시/텍스처·정적/동적·H3/P2 선택 → 설계 먼저 → 부품 수와 Tripo 예상 크레딧 확인 → 이 설계로 생성** 순서로 사용합니다. 마지막 확인 전에는 Tripo 유료 생성을 제출하지 않습니다. 설계는 로컬 개발용 Codex 구독의 기본 `gpt-6-luna/high`, H3가 기본 선택입니다. 생성물과 소유권은 기존 로컬 서버 저장소에 남습니다. 이 실행 방식은 이 PC의 개발 환경용이며 외부 공개 서버를 여는 기능이 아닙니다. 게임을 종료한 뒤 서버를 끄려면 [Stop_Tripo_Server.cmd](Stop_Tripo_Server.cmd)를 실행합니다. 배포 폴더의 `Play.cmd`는 별도의 무과금 샘플 모드입니다.

### LLM 비교와 검증

`artifacts/model-benchmark*/index.html`은 저장된 모델/effort 결과의 행동 검사와 API 환산 비용 보고서입니다. 실제 실험은 로컬 Codex 구독으로 실행했고 **GPT API 현금 과금은 0**입니다. 환산은 CLI의 전체 토큰 사용량과 공개 단가, 가정 환율 1달러=1,400원으로 계산합니다. 실제 서비스 프롬프트의 청구액과 같지 않습니다. v1/v2는 계약 설명이 달라 서로 같은 조건의 비교로 합치지 않습니다.

이미지 입력 36회 비교에서는 Luna high가 화병·풍차·상자 세 과제의 동작을 모두 충족했고, 평균 API 환산액은 약 2.67원이었다. 이미지 없는 강화 검사에서는 동일 설정이 2/3이므로 모든 가구의 성공을 보장하지 않는다. JSON 형식 강제, 높은 effort, 오류별 수정 안내는 다른 실험 조건으로 분리했다. `artifacts/review/index.html`에서 조건·모델·effort를 선택하고 실제 출력 비교 영상을 확인한다.

## 플레이 순서와 완료 기준

1. **마을**: WASD 이동. 기본 의자를 보관함에서 선택하고 팔레트로 전체 색을 바꿉니다. `선택한 물건 놓기` → 바닥 클릭. R은 90도 회전, Esc는 취소입니다. 위치·색이 재접속 후 남으면 완료입니다.
2. **탐험**: `탐험 지도 →`에서 지역·난이도를 선택합니다. 1일 60초, 총 약 7분입니다. E 채집, Q 먹기, F 모닥불, H 붕대, Space 공격, Shift 달리기. 목재·돌·열매·섬유로 도끼·창·수프·붕대를 만듭니다. 밤은 매일 39초부터입니다. 나무와 돌은 이동을 막으며 자원은 두 게임일 후 재생됩니다. 나무·돌이 플레이어나 적과 겹치면 재생을 잠시 미룹니다. 밤마다 목재 두 개 이상을 남겨 두세요.
3. **생존 보상**: 일곱 번째 밤이 끝나면 서버가 채집·처치·남은 체력의 기본 성과 35~100에 지역·난이도 배율을 곱하고 내림하여 별씨를 계산합니다. `마을로 / 결과 받기`로 수령합니다. 중도 귀환·사망에는 완주 보상이 없습니다. 수령 전에 종료해도 마을의 미수령 보상 버튼으로 회수할 수 있습니다.
4. **공방**: 25 별씨로 생성합니다. 샘플 모드에서는 프롬프트에 관계없이 직접 만든 의자가 나옵니다. 실제 AI 생성이라고 표시하지 않습니다. 새 물건이 보관함에 도착해 색칠·배치되면 로컬 연동 검증 완료입니다.

기본 환영 재화 80 별씨는 demo 전용입니다. live 서버는 환영 재화를 지급하지 않습니다. 별씨는 현재 게임 내 숫자 재화이며 현금 결제·출금 기능이 없습니다.

I 키로 오른쪽 보관함/탐험 가방을 접고 펼치며, 마우스 휠로 확대·축소합니다. M은 게임 소리 켜기/끄기입니다. 채집 가능한 가장 가까운 자원을 금색 고리로 표시합니다. 재료가 부족하거나 이미 보유한 도구는 제작 버튼이 비활성화됩니다. 도끼·창을 만들면 움직이는 캐릭터 손에 표시됩니다. 마을의 숲 입구 가까이에서는 E로 입장할 수 있습니다.

생존 중 Esc는 일시 정지 메뉴입니다. 저장 귀환과 도전 포기는 다릅니다. 음식은 가방에서 원하는 것을 클릭할 수 있으며, Q는 수프를 우선 사용합니다. 달리기는 초당 기력 22를 쓰며 걷거나 쉬면 초당 14를 회복합니다. 기력이 소진되면 잠시 달릴 수 없습니다.

## 연동 검증의 범위

- 실제 Godot ↔ 로컬 HTTP 서버: 가입, 잔액, 소유 GLB 다운로드, 전체 색칠, 배치, 숲 이동/채집/모닥불, 샘플 생성, 재로그인 저장 복원까지 자동 테스트 통과.
- 서버 테스트: 타인 접근, 오래된 버전, 중복 요청, 동시 구매, 세션 만료, 잔액 부족, 허위 위치/시간/점수, 보상 중복, 7일 생존, 저장 복원 검증.
- 실제 Tripo 어댑터를 모의 HTTP 응답으로 연결: 잔액 → 작업 제출 → 조회 장애 후 같은 task 재조회 → GLB 다운로드 → 소유자 전달 검증. API 키 헤더가 자산 서버에 전달되지 않는 것도 검사.
- Tripo 401 및 HTML 400 응답을 각각 정리된 오류 코드로 처리합니다. 원문 응답·키는 출력하지 않습니다.
- **2026-10-01 실제 Tripo 인증 및 잔액 조회 성공: 0.0 크레딧.** 사용자 지정 키 파일을 서버 측에서만 읽었습니다. 키와 원문 응답은 출력하지 않았습니다. 잔액이 없어 유료 생성 요청은 실행하지 않았으며, 실제 생성 성공은 미검증입니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1 -Capture
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1 -Capture -Night
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1 -Capture -Combat
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1 -Capture -Night -Loss -Packaged -PortableServer
powershell -ExecutionPolicy Bypass -File .\tools\test.ps1 -Capture -FullRun -Packaged -PortableServer
```

Night 검증은 실제 첫 밤까지 약 45초 걸립니다. Combat은 실제 채집·제작 후 밤에 회피·처치를 검사합니다. Loss는 별도 도전에서 실제 사망·무보상·재도전을 확인합니다. FullRun은 시간이나 체력을 주입하지 않고 실제 게임 입력으로 약 7분을 플레이합니다. 별도의 빠른 서버 테스트에서는 주입 가능한 시계로 전체 규칙을 검사합니다. 공개 API에는 시간 가속 기능이 없습니다. 스크린샷과 실행 로그는 `artifacts/`에 생성됩니다. 최초 GLB 충돌 테스트는 `tools/run_game.ps1 -Check`로 실행합니다.

## Tripo를 실제 계정으로 연결할 때

서버는 `TRIPO_API_KEY` 환경변수 또는 `TRIPO_API_KEY_FILE`이 가리키는 UTF-8 비밀 파일 중 하나만 읽습니다. 파일은 프로젝트 밖에 두고 서버 운영 계정만 읽을 수 있게 관리합니다. 게임에는 전달하지 않습니다. UTF-8 BOM, 한 줄 키, `TRIPO_API_KEY=...` 형태를 지원하며 잘못된 파일은 내용을 출력하지 않고 거부합니다.

```powershell
.\.tools\server-venv\Scripts\python.exe .\tools\check_tripo.py --key-file "$env:USERPROFILE\Desktop\tripo_key.txt"
```

실제 생성은 별도 live 저장소, HTTPS, 초대 코드, `TRIPO_ENABLE_PAID=true`, 공급자 잔액이 모두 갖춰져야 작동합니다. 기본 모델은 `P2-20260801`, texture/pbr/export_uv는 false입니다. 기본 일일 제출 한도는 5회이며, 공급자 작업은 전역 하나만 진행합니다. `TRIPO_RESERVE_PER_JOB=200`은 잔액 최소 기준 설정값으로 실제 생성 가격의 확약은 아닙니다.

세부 배포 조건은 `docs/DEPLOYMENT.md`, 권한·거래·파일·재시도 정책과 한계는 `docs/SECURITY.md`를 확인하세요. 데모 DB를 live로 바꾸거나 게임 클라이언트에 Tripo 키를 넣어서는 안 됩니다.

## 아트와 현재 한계

Scenario에서 탐험가 원화, 탐험가 3D, 공방 건물과 캐릭터 리깅·걷기·대기 동작을 생성해 게임에 적용했습니다. 걷기와 대기는 같은 뼈대에 합쳤으며 애니메이션이 서버가 관리하는 이동 위치를 바꾸지 않도록 수평 이동량을 제거했습니다. 도구는 손 뼈대를 따라갑니다. Scenario 오디오 두 개는 자동 설명이 요청과 달라 검토용 ZIP만 보관하고 게임에는 포함하지 않았습니다. 배경음과 효과음은 직접 합성한 원본을 사용합니다. 자세한 기록은 `docs/ASSETS.md`에 있습니다.

마을/생존 맵은 직접 구성한 도형 아트와 Scenario 공방·캐릭터를 함께 사용합니다. 행동 동작은 걷기·대기 클립 위에 절차적으로 합성하며 전문 모션 캡처 수준은 아닙니다. 온라인에서 여러 플레이어가 동시에 같은 마을에 보이는 기능, 부분 브러시 색칠, 콘텐츠 검수, 운영자 복구 UI는 아직 없습니다. 운영자 복구는 서버 터미널 명령으로 제공하며 공개 API로 노출하지 않습니다. 서버 통제는 구현·테스트한 범위이며 완전한 보안 인증을 뜻하지 않습니다. 로컬 서버를 소유한 사람은 로컬 DB를 수정할 수 있으므로 실제 거래는 운영자가 관리하는 원격 서버가 필요합니다.

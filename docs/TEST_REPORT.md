Night 실행은 실제 첫 밤까지 기다린다. 최종 검사에서는 독립 서버 EXE와 배포 PCK를 연결해 렌더링·채집·모닥불·밤·샘플 생성·재접속을 확인했다. 공식 release 템플릿은 경로 덮어쓰기를 허용하지 않으므로 외부 테스트 스크립트를 release EXE에 직접 주입하는 방식은 사용할 수 없다. 동일한 배포 PCK를 Godot 실행기에서 검사하고 release EXE는 별도 시작 검사를 했다.

생성 작업 완료와 보관함 갱신이 겹칠 때 검사 타이밍 오류가 한 번 발생했다. 클라이언트가 보관함 갱신을 기다리도록 수정하고 렌더 통합 및 최종 headless 통합을 다시 통과했다.

임의 자원이 캠프 근처 시작 자원을 가리는 경우를 발견했다. 캠프/시작 자원을 먼저 배치하고 다른 자원과 최소 간격 2.2를 유지하도록 수정했다. 100개 시드의 간격·경계 검증과 실제 렌더 통합을 통과했다.

추가 서버 검사는 비밀 파일 형식/오류 비노출, 온라인 백업→복원→로그인/소유 GLB 확인, 복원 시 과거 세션 폐기와 생성 보류, 경로 탈출/파일 변조 거부, 완료한 생성 작업의 중복 전달 차단을 검사한다.

개인 GLB 검증에는 음수 접근자/노드/메시 인덱스, 잘못된 장면 루트, 불완전한 transform, 비정수 count, 빈 primitive 및 JSON 루트 타입 오류의 거부 검사도 추가했다.

운영자 복구 검사는 공급자 task 재연결 시 새 유료 제출이 없는지, 미제출 확인 없는 환불·중복 환불·이미 알려진 task 변경이 거부되는지 확인한다. 이 CLI는 서버에 직접 접근 가능한 운영자용이며 공급자 미제출 여부를 자동으로 증명하지 않는다.

pytest에는 Starlette가 테스트용 httpx 사용을 향후 변경할 예정이라는 deprecation warning 1개가 남는다. 테스트 실패나 런타임 오류는 아니다.

0.4에서는 가방의 초기 접힘 상태, 소유 GLB의 3D 미리보기, 로그아웃 시 미리보기 제거, 두 맵의 배경음 리소스와 재생 상태를 추가 검사했다. 게임 화면의 배치·색칠·소유권 처리는 기존 서버 API를 그대로 이용한다. 최종 실제 밤 장면에서 이 PC의 순간 측정값은 144 FPS, 979 draw calls였다. 지속 부하 벤치마크나 다른 장치의 성능 보장은 아니다.

렌더 테스트 종료 직후 ObjectDB 객체 2개 정리 경고가 한 번 발생했다. 상세 로그에서 반복 재생 중인 AudioStreamWAV/PlaybackWAV 참조임을 확인하고, 소리 노드가 종료될 때 재생·트윈을 중단하고 스트림을 해제하도록 수정했다. 테스트 장면도 렌더 프레임 완료 후 종료한다. 수정 후 시작·종료 검사에서는 오디오 정리 경고가 재발하지 않았다. 상세 엔진 로그에는 샘플 GLB의 생략된 byteStride를 연속 배열로 읽는다는 안내 경고가 나온다. 모델 가져오기와 정규화·색칠·배치는 통과한다.

Tripo live 생성 어댑터는 MockTransport로 전체 경로를 검사했다. 별도의 실제 계정 인증/잔액 조회는 성공했지만, 잔액 0으로 유료 생성 요청은 하지 않았다. 호스팅·TLS·Docker 빌드·다중 사용자 부하·침투 테스트는 수행하지 않았다.

최초 로컬 네트워크 테스트의 임시 계정/DB는 `artifacts/initial-local-test-data/`에 보존했다. 이후 테스트는 매번 별도 `artifacts/qa-*` 저장소와 8766 포트를 사용한다. 일반 실행의 `server-data/`와 8765 포트에 테스트 계정이 생성되지 않는다.
## 이전 개발 범위 조정 확인 (0.5 작업 전)

거래 UI를 비활성화하고 맵·캐릭터·7일 생존·생성 연동을 우선 범위로 정리했던 시점의 기록이다. 기존 거래 API와 저장 데이터를 유지했다. 당시 서버 20개, Godot HTTP 통합 18개 검사를 통과했고 Windows 게임 내보내기에 성공했다. 그 범위 조정 작업에서는 실제 7분을 완주하지 않았다. 위 0.5의 실시간 완주 결과는 이후 별도로 실행한 것이다.

Villagen 개발 서버 (학교 서버와 같은 AWS VM)
=============================================

학교 서버(https://54-117-10-64.sslip.io, school-release 브랜치)는 그대로 두고, 같은 VM에 개발 서버를 하나 더 둡니다.
· 주소: https://dev.54-117-10-64.sslip.io  (sslip.io 가 dev. 이 붙은 이름도 같은 IP로 알려 줘서, 같은 Caddy가 인증서를 받습니다)
· 코드: dev 브랜치. dev 에 push 하면 5분 안에 개발 서버만 다시 만들어집니다. 점검 공지는 없습니다.
· 제작: 기본은 가짜(fake) — Tripo 대신 서버 안의 대역이 바로 샘플 모양을 돌려줍니다. 키를 넣지 않고 비용 0.
  필요할 때만 진짜(real) Tripo로 바꾸고, 그때는 개발 서버만의 작은 예산(예: 300 크레딧)을 씁니다.
· 【명령】 표시가 붙은 줄만 서버 창(EC2 Instance Connect)에 한 줄씩 붙여넣습니다. 나머지는 설명입니다.

무엇이 따로이고 무엇을 같이 쓰나
  따로: 체크아웃(/opt/villagen-staging), 컨테이너(villagen-staging), 데이터(villagen_staging_data),
        설정(/opt/villagen-staging/ops/staging.env), 초대 코드, 관리자 계정, 예산 사용량, 자동 업데이트 타이머와 기록
  같이: VM, HTTPS 입구(Caddy), real 모드일 때만 학교 서버의 Tripo/Gemini 키 파일(읽기 전용)
  · 개발 서버는 학교 서버의 데이터, 컨테이너, 초대 코드, 사용량 키를 읽지도 쓰지도 않습니다.
  · 학교 서버 업데이트(ops/update_online_server.sh, 자동 업데이트)는 개발 서버를 다시 만들지 않고, 그 반대도 같습니다.
  · 학교 서버가 업데이트하는 동안에는 개발 서버가 빌드하지 않고 다음 차례(5분 뒤)로 미룹니다.
  · 메모리: 학교 서버 640MB + Caddy 96MB 는 그대로, 개발 서버는 최대 320MB(CPU 1개분)입니다.

------------------------------------------------------------
처음 한 번: 설치
------------------------------------------------------------
먼저 학교 서버가 이 기능이 들어간 버전으로 업데이트되어 있어야 합니다(ops/install_staging.sh 가 있는 버전).
아니면 설치 명령이 "아직 개발 서버를 모르는 버전이에요"라고 알려 주고 아무것도 바꾸지 않습니다.

【명령】 cd ~/tripo_s1
【명령】 sudo bash ops/install_staging.sh

· 처음 한 번은 Caddy(HTTPS 입구)를 다시 켜도 되는지 묻습니다. y 를 누르면 학교 서버 접속이 2~5초 끊겼다가 돌아옵니다
  (게임은 스스로 다시 연결합니다). 플레이어가 적을 때 하세요. 인증서는 그대로 남습니다.
· 그다음 dev 브랜치를 /opt/villagen-staging 에 받고, 개발 서버를 처음 빌드합니다(몇 분 걸림).
· 끝에 https://dev.54-117-10-64.sslip.io/health 결과가 나오고 "environment": "staging", "tripo_fake": true 가 보이면 끝입니다.
  처음에는 인증서를 받느라 1~2분 응답이 없을 수 있습니다. 조금 뒤 아래 status 로 다시 확인합니다.
· 다시 실행해도 됩니다(고장 났을 때 고치기, 설정 새로 쓰기). 데이터와 설정은 그대로 둡니다.

------------------------------------------------------------
매일 쓰기
------------------------------------------------------------
· dev 브랜치에 push → 5분 안에 개발 서버만 새 코드로 다시 만들어집니다. 따로 할 일은 없습니다.
· 같은 커밋이 빌드에 실패하면 다시 시도하지 않고, dev 에 새 커밋이 오면 다시 시도합니다.

【명령】 sudo bash ops/staging.sh status
  주소, 제작 방식, 배포된 커밋과 dev 최신 커밋, 메모리(학교 서버 포함), /health, 자동 업데이트 기록을 봅니다.

【명령】 sudo bash ops/staging.sh logs
  개발 서버 로그 200줄. 계속 보려면 logs -f (Ctrl+C로 끝), 자동 업데이트 기록은 logs update 입니다.

【명령】 sudo bash ops/staging.sh update --force
  기다리지 않고 지금 dev 를 받아 다시 만듭니다(실패했던 커밋도 다시 시도).

------------------------------------------------------------
가짜 제작 ↔ 진짜 Tripo
------------------------------------------------------------
진짜 Tripo로 (예산 300 크레딧, 한 번 제작 최대 10 크레딧):
【명령】 sudo bash ops/staging.sh real --budget 300

  · --budget: 개발 서버가 쓸 수 있는 Tripo 크레딧 총량(1~2000, 처음에는 꼭 적기). 다 쓰면 개발 서버의 제작만 멈춥니다.
  · --max-credits 20: 한 번 제작에 쓸 수 있는 크레딧(기본 10 = 가장 싼 제작만, 색 입힌 가구는 20).
  · --no-gemini: Gemini 설계 없이 Tripo만 씁니다(기본은 학교 서버에 Gemini 키가 있으면 같이 씀).
  · 학교 서버와 같은 Tripo 계정에서 크레딧이 나갑니다. 예산은 개발 서버 데이터에만 기록됩니다(가짜 제작은 0으로 셈).
  · 사용량 보기: status 의 /health 줄에 "tripo_budget": {"used": 사용량, "total": 300}

가짜 제작으로 되돌리기(키가 컨테이너에서 빠짐):
【명령】 sudo bash ops/staging.sh fake

  · 바꾸는 동안 개발 서버만 10~20초 다시 켜집니다. 학교 서버는 영향이 없습니다.
  · 만드는 중인 제작이 있으면 바꾸지 않고 알려 줍니다. 그 제작을 포기하고 바꾸려면 끝에 --force 를 붙입니다.
  · 가짜 제작에서 작업 진행 막대를 보고 싶으면 /opt/villagen-staging/ops/staging.env 의 STAGING_FAKE_SECONDS=20 으로 바꾼 뒤
    sudo bash ops/staging.sh fake 를 한 번 더 실행합니다.

------------------------------------------------------------
초기화, 끄기, 관리자
------------------------------------------------------------
개발 서버 데이터를 모두 지우고 새로 시작(계정, 마을, 만든 물건, 제작 기록, 예산 사용량):
【명령】 sudo bash ops/staging.sh reset
  "reset" 이라고 입력해야 지웁니다. 학교 서버의 데이터는 그대로입니다. real 예산 사용량도 0부터 다시 셉니다.

메모리가 모자랄 때 잠시 끄기 / 다시 켜기 (끄면 자동 업데이트도 멈춤):
【명령】 sudo bash ops/staging.sh stop
【명령】 sudo bash ops/staging.sh start

개발 서버 전용 관리자 계정(학교 서버와 다른 비밀번호, 화면에서 두 번 입력):
【명령】 sudo bash ops/staging.sh admin devadmin

개발 서버를 없애기 (데이터와 체크아웃은 남김 / --purge 를 붙이면 그것까지 지움):
【명령】 sudo bash ops/install_staging.sh --remove
  dev 주소를 Caddy에서 빼는 것은 연결을 끊지 않는 재적용이라 학교 서버는 끊기지 않습니다.

------------------------------------------------------------
게임에서 접속하기
------------------------------------------------------------
· 지금 게임: 로그인 화면의 [월드] → [직접 입력] → https://dev.54-117-10-64.sslip.io
· 나중의 DEV 게임(개발용 빌드): 이 주소를 기본 월드로 넣으면 됩니다. /health 의 "environment": "staging" 으로 개발 서버인지 알 수 있습니다.
· 가입: 초대 코드로만 가입합니다(팀 3명에게만 공유). 새 계정은 별씨 1000개로 시작합니다.
  초대 코드 보기: sudo cat /opt/villagen-staging/ops/staging-secrets/registration-code
  누구나 가입하게 바꾸려면 staging.env 의 STAGING_OPEN_REGISTRATION=true 로 바꾼 뒤 fake 또는 real 명령을 한 번 실행합니다.
· 학교 서버의 계정은 개발 서버에 없습니다. 개발 서버에서 따로 가입합니다.

------------------------------------------------------------
이럴 때는
------------------------------------------------------------
· status 에 "응답 없음": 처음 설치 직후면 1~2분 기다립니다. 계속되면 logs 와 logs update 를 저에게 보여 주세요.
· 메모리가 부족해 학교 서버가 느려지면: sudo bash ops/staging.sh stop. 학교 서버가 먼저입니다.
· 설정 파일: /opt/villagen-staging/ops/staging.env (키나 초대 코드는 넣지 않습니다). 바꾼 뒤에는 fake 또는 real 명령을 한 번 실행하면 적용됩니다.

### 수정 근거와 경계

- M1: `server/display_names.py`의 `check_policy()`는 저장 문자열이나 `key()`를 바꾸지 않는다. 정책 검사에만 NFKC/NFKD, 대표 Greek/Cyrillic/Latin 치환, 악센트 제거, 구분자 결합, 기존 한글 자모 조합과 금칙어 목록을 적용한다. 모든 Unicode 동형문자나 언어별 우회가 해결됐다는 의미는 아니다. 다국어·일반 이름의 정상 사례도 회귀 검사하며, 운영상 오탐은 검토가 필요하다.
- M2/M3: `server/app.py`의 `register()`와 `edit_name()`에서 처리한다. 가입 정책 거부는 비밀번호 해시·계정/보상 생성 전에 이뤄진다. 로그인 처리와 기존 계정명은 바꾸지 않는다. 표시명 UNIQUE 인덱스와 `BEGIN IMMEDIATE`를 유지해 동시 이름 선점·동일 계정 동시 개명에서도 한 요청만 성공하도록 검증한다.
- M4: `server/quest_board.py`의 `accept()`/`progress()`를 수정했다. 계정 기준 낮/밤 각각에서 반대 시간대 헤더를 보내도 낮에는 야간 진척·보상 지급이 거부되고 밤에는 진행되는 4개 회귀 사례를 추가했다. 퀘스트 수락 자체는 낮에도 가능하며 표시용 시각은 그대로다.
- M5/M6: `server/tripo_budget.py`의 `legacy_bills()`를 `legacy_credits()`/`manage_job()`에서 공유한다. 미확정/미수신 청구는 견적을 보존하고, 이관 시 기존 예약·견적·실제 청구 중 더 큰 부채를 보존한다. 테스터 합계도 구 참조로 식별한 작업의 과다 청구를 이관 전부터 반영한다. 현재 계정 역할만으로 일반 작업을 테스터 사용량에 넣지 않는다. 새 원장으로 이관한 비용은 작업 삭제나 재시작으로 사라지지 않는다. 실제 비용이 견적보다 작아도 이관 과정에서 견적을 보수적으로 유지할 수 있는 기존 특성은 그대로다.

## 0.11.8 DB 복사본 마이그레이션

`test_security_0119_boundaries.py`에서 0.11.8 형태의 사용자·구 아바타·생활 상태·잔액·원장·물건·제작 작업·presence·채팅 테이블을 메모리 SQLite에 만들고 `backup()`으로 별도 메모리 DB에 복사했다. 복사본에 실제 앱 초기화의 전체 스키마 업그레이드를 적용하고 다시 시작해 멱등성을 검사한다.

검증 항목은 구 ranger→f1 매핑, 아바타 원문/버전 백업, 선택 플래그, 기존 색/버전·잔액·생활 JSON·원장·물건·완료 작업·채팅 보존, 신규 기능 테이블 생성, `foreign_key_check` 무결함과 `integrity_check=ok`다. 원본 메모리 DB의 스키마/아바타는 그대로인지도 검사한다. 기존 avatar8의 손상 JSON·모든 구 캐릭터·구 요청 재전송·재시작 테스트와 폴링 인덱스 롤백 테스트를 함께 사용한다.

이것은 합성한 0.11.8 스키마 복사본이며 실제 운영 백업 전체를 대체하지 않는다. 운영 고유 데이터, 중간 버전 수동 스키마 변경, 구 비용 원장과 실제 청구 차이까지 보장하지 않는다.

5. 구 `tester_credit_spend`/`studio_jobs.parts`에 rig/anims 작업이 있는지, `tripo_job_holds`로 이미 관리되는지 대조한다. 수정된 집계가 서버/테스터 양쪽에서 저장된 실제 청구를 포함하는지 확인하고 공급자 장부와 대사한다. 구 작업을 `manage_job()`으로 이관할 경우 복사본에서 트랜잭션으로 검증한 뒤 적용한다. 운영 DB에는 이 작업에서 어떠한 이관 명령도 실행하지 않았다.

### 배포 직후

- 모의/승인된 시험 계정으로 가입·표시명 거부·동시 이름 선점·프로필 선택과 0.11.8 클라이언트 구 캐릭터 호환을 확인한다. 이 감사는 실제 공급자를 호출하지 않았다. 비용 발생 시험이 필요하면 담당자가 별도 승인된 절차로 수행한다.
- 비운영자 기존 display_name/username에서 예약어·금칙어 우회가 이미 저장돼 있는지 점검한다. 자동 개명하지 않았으므로 발견 시 변경 이력·고유키·사용자 안내와 함께 정리한다. 로그인 식별자는 임의로 변경하지 않는다.
- 시간대 헤더를 바꿔도 야간 보상이 늘지 않는지, 동일 요청/새 request_id 재시도로 편지·게시판 보상이 중복되지 않는지, 추방/만료 이후 집 자산을 읽을 수 없는지 확인한다.
- 비용 모니터에서 unknown/reserved/실제 청구와 서버·테스터 합계를 관찰한다. `rigging_disabled`, 한도 초과, 이름 정책 거부, EconomyRejected 급증을 확인한다. 비밀값·세션 토큰은 점검 출력에 남기지 않는다.
- L1은 시각 유사 이름을 검토하는 정책과 기존 충돌 목록을 먼저 만들고 중복키 마이그레이션을 설계한다. L2는 이름 저장 전용 쓰기 한도와 requests/audit 보존 정책, L3는 서버 이동 검증을 별도 변경으로 다룬다. 이전 0.11.8 감사의 다계정 보상 이전·로그인 잠금 악용 같은 정책 과제도 이 보고서로 해소됐다고 보지 않는다.

## 검증 기록

모든 검증은 로컬 SQLite, TestClient, in-process fake/모의 공급자를 사용한다. 외부 호출·실제 Tripo/LLM 호출, 배포, push, 커밋은 수행하지 않았다. `game/`과 운영 설정/비밀 파일은 수정하지 않았다.

실행 명령은 사용자의 최신 지시에 따라 작업 파일의 `.codex-tmp\pytest` 대신 `.codex-tmppytest`를 사용한다.

```powershell
& 'C:\lsm26\triphthonS1\.tools\server-venv\Scripts\python.exe' -m pytest server/tests -q --basetemp=.codex-tmppytest -p no:cacheprovider
```

최종 전체 실행은 **1,774 passed, 5 skipped, 1 warning, 실패 0개**로 종료했다(exit code 0, 1,190.18초 / 19분 50초). `git diff --check`도 통과했다. 경고 1개는 설치된 Starlette TestClient의 httpx 사용 중단 예고이며 이번 감사에서 의존성을 변경하지 않았다.

신규 보안 회귀는 총 **73개 사례**로, `test_security_0119_boundaries.py` 8개, `test_security_0119_economy.py` 4개, `test_security_0119_profile.py` 52개, `test_security_0119_rig.py` 9개가 모두 통과했다. 기존 테스트의 공개 가입 예약어 기대값, 관리자 시간 테스트 계정명, 구 테스터 비용 기대값을 수정에 맞춰 조정했다.

검증 과정에서 후보의 기존 테스트 기대값 3곳을 바로잡았다. `test_chat.py`는 구 채팅 `messages`에 `display_name`을 기대했지만 `173e7bae`/현재 HEAD는 구 응답 네 필드를 의도적으로 보존한다. 반대로 `test_polling_performance.py`의 파티 응답 기대값에는 이미 지원하는 `display_name`이 빠져 있었다. 서버 응답은 바꾸지 않고 각각의 계약에 맞췄다.

`test_quest_content_0119.py`는 서버 의뢰·편지 대상 19명과 클라이언트 주민 전체가 같다고 가정했으나 이후 `boni`/`sol`이 클라이언트에 추가됐다. 기존 19명 전체의 문안·보상 연결 검증은 유지하고, 클라이언트에만 있는 두 명을 명시적으로 구분했다. 다른 누락/추가 주민이 생기면 여전히 실패한다. 두 신규 주민에게 서버 의뢰나 보상을 임의로 추가하지 않았으므로 해당 콘텐츠 확장이 필요하면 별도 기획·통합 작업이 필요하다.

채팅 이력 성능 테스트의 준비 데이터 2만 건은 한 트랜잭션으로 삽입하도록 바꿨다. 실제 검사하는 조회·결과·SQL 명령 수 상한은 그대로이며 불필요한 2만 번의 개별 디스크 동기화만 없앴다. 신규 테스트 준비 중 잘못된 테이블명과 하루 경과 후 세션 만료를 고려하지 않은 테스트도 교정했다. 중간 실패·중단 결과를 최종 통과 수에 포함하지 않는다.

기존 `test_polling_performance.py`의 제거된 작물 캐시 전용 3개 함수(매개변수 포함 5개 사례)는 기존 skip 상태를 유지했다. 이유와 대체 농사/방문 테스트는 `docs/coordination/SKIPPED_TESTS_0119.md`에 이미 기록돼 있다. 이번 감사에서 새로 skip/xfail 처리한 테스트는 없다.

테스트 종료 후 `.codex-tmppytest/` 삭제 명령은 자동 승인 검토의 `blocked by policy` 거부로 실행되지 않았다. 이 임시 폴더는 작업 트리에 남아 있으며 통합 대상이 아니다. `CODEX_TASK.md`도 원래의 미추적 상태로 두었고 커밋하지 않았다.

## 생성 실패 진단과 LLM 전환

기존 OpenAI 경로는 여러 HTTP 오류를 `llm_request_failed`로 합쳤고, Gemini는 같은 회사 내 모델 재시도만 있었습니다. 새 코드는 다음 원인을 구분합니다.

| 원인 | 표시·동작 |
|---|---|
| 명시적인 정책 거절 | 정책 검사로 멈췄다고 안내. 구체적 사유가 없으면 임의로 추정하지 않음. 다른 모델로 재시도하지 않음 |
| Gemini RECITATION / IMAGE_RECITATION | 기존 자료와의 유사성 검사로 분리. 저작권 침해 판정이라고 표시하지 않음 |
| 429 요청 제한 / 5xx 과부하 | 원인 코드 분리. 설정된 다른 제공자로 전환 가능 |
| 시간 초과 / 연결 장애 | 각각 분리. 설정된 다른 제공자로 전환 가능. 앞선 호출의 사용량이 확인되지 않으면 미확정 표시 |
| 사용 불가능한 모델 | 설정된 모델·보조 제공자를 제한된 순서로 시도 |
| 잔액·지출 한도 부족 / 인증·권한 문제 | 운영 설정 문제로 종료. 자동으로 예산 제한을 넘기지 않음 |
| 설계 JSON·동작 검증 실패 | 기존 1회 수정 한도 유지. 다른 제공자로 무한 재시도하지 않음 |
| Tripo 생성·뼈대·애니메이션 실패 | LLM 실패와 구분. 이미 제출된 유료 3D 작업을 무조건 새로 제출하지 않음 |

OpenAI↔Gemini 전환을 구현했습니다. `TRIPOTHON_STUDIO_LLM`이 주 제공자이고, `TRIPOTHON_STUDIO_LLM_FALLBACKS=gemini,openai`가 보조 순서입니다. 중복 제공자는 제외하며 서버에 키가 있는 제공자만 선택합니다. 기본값은 빈 보조 목록입니다. 운영 키를 새로 발급하거나 운영 서버 설정을 변경하지 않았으므로 **운영 자동 전환 활성화는 아직 아닙니다**.

기존 유료 서버 구성 위에 추가할 `ops/compose.llm-fallback.yaml`을 준비했습니다. 서버의 `ops/secrets/openai-key`와 `ops/secrets/gemini-key`가 모두 준비되어야 합니다. 기존 배포 파일 목록의 마지막에 이 파일을 추가하면 됩니다. 키를 문서나 클라이언트에 넣지 않습니다. 실제 계정의 사용 가능한 모델은 별도 확인이 필요합니다.

모든 실제 호출·수정·전환은 기존 일일 호출 예산에 포함됩니다. 제공자별 시도와 오류 코드, 알려진 사용량을 저장합니다. 비용 집계에서도 전환 전후 토큰을 각 제공자에 귀속합니다. 타임아웃으로 사용량을 모르면 0원이라고 처리하지 않습니다. 원본 요청/비밀키/상위 서비스의 원문 오류를 새 진단 항목으로 노출하지 않습니다.

확인한 세 로컬 체크아웃의 기본 `server-data`에서 운영 제작 이력 DB를 찾지 못했습니다. 따라서 과거 실패가 저작권·심의·과부하 중 무엇이었는지는 아직 확인되지 않았습니다. 다음 실패는 새 코드와 시도 이력으로 구분할 수 있습니다. Tripo 자체의 가용성에는 여전히 의존합니다.

공식 근거: [OpenAI 오류 코드](https://developers.openai.com/api/docs/guides/error-codes), [Gemini 문제 해결](https://ai.google.dev/gemini-api/docs/troubleshooting), [Gemini 종료 사유](https://ai.google.dev/api/generate-content#FinishReason). 사용자에게 표시하는 분류와 전환 범위는 이 프로젝트의 구현 정책입니다.

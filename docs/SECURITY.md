# 보안 경계와 현재 검증 범위

이 코드는 대회 시연용 단일 서버 프로토타입이다. 공개 서비스 보안 심사나 침투 테스트를 완료한 제품은 아니다.

## 0.8 생성 가구와 실행 경계 · 2026-10-02

- 다중 부품 백업은 공개된 manifest와 미완성 작업의 다운로드 완료 파일을 모두 수집하고 SHA-256을 확인한다. 복원된 미완료 작업을 자동 결제/재전송하지 않는다. 운영자 조정은 사전 백업·조사 참조·원장 검증을 요구하며 HTTP 관리 API로 노출하지 않는다.
- 이야기 해금과 첫 완료 보너스는 서버 생존 상태와 계정별 완료 기록으로 결정한다. 같은 장의 여러 승리를 동시에 청구해도 첫 완료 보너스는 한 번만 지급하며, 자유 탐험 보상과 구분해 원장에 남긴다.

- `/v1/studio/jobs`는 텍스트 최대 1,500자와 PNG/JPEG 1MB·2048px까지 받는다. 이 경로만 요청 본문 1.5MB를 허용하고 일반 JSON 한도는 8KiB다.
- LLM 출력은 최대 8부품의 구조와 숫자 AST다. 문자열을 Python/GDScript/eval로 실행하지 않는다. 새 함수와 이벤트는 유한 수치·깊이·호출·반복·명령·연산 예산을 검사한다. 실패한 이벤트/함수는 상태와 명령을 함께 되돌린다. 파일/HTTP/재화/DB 접근 연산은 없다.
- `/assembly`, `/parts`, `/event`, `/invoke`, `/colors`, `/bindings`, `/placement`는 매 호출마다 세션과 현재 소유자를 검사한다. 수정은 판매 상태와 객체/런타임 버전을 추가 검사한다. 회전축/크기 보정은 개인 인스턴스에만 저장하며 공용 원본 GLB와 생성 설계는 유지한다.
- 생성 GLB는 20MB 이하의 내장 데이터만 허용한다. 외부 URI, 확장, 스킨, 애니메이션, 잘못된 참조/인덱스/부동소수점, 과도한 노드·인스턴스·드로우콜·이미지를 거부한다. 부품 텍스처는 PNG/JPEG·4096px·총 2,400만 픽셀, 새 조립물 전체는 48MB·3,200만 텍스처 픽셀·30만 정점·128드로우콜 예산이다. 해시를 검증한 뒤 메모리에서 조립한다.
- 게임 재화와 제공사 크레딧은 별도 원장이다. 예약금 후 부품 수·모델·이미지 편집을 반영한 최종 별씨를 제시한다. 확인 시 부족 금액을 트랜잭션으로 차감해야 유료 요청이 가능하다. 실패하면 아직 환불하지 않은 게임 재화만 환불한다. 이미 소비한 실제 Tripo 비용은 실패 결과에도 보존한다.
- 유료 POST 전에 submitting을 저장한다. 응답이 불명확하면 unknown으로 멈추고 자동 재제출하지 않는다. 알려진 작업 ID는 조회/다운로드만 재시도한다. DB 작업 임대와 갱신으로 작업자의 동시 제출을 방지한다. 키가 사라진 알려진 작업은 설정 복구를 기다린다.
- 로컬 Codex 어댑터는 개발 demo 전용이며 live에서 거부한다. 도구/셸/웹/멀티 에이전트를 끈 단발 설계 실험이다. 서비스용 어댑터는 별도 OpenAI API 키를 서버에서 사용한다. 실제 OpenAI API 호출은 아직 하지 않았다.

클라이언트의 가까이/떠나기 이벤트와 연속 애니메이션 시간은 장식 동작이다. 서버가 모든 실내 보행·렌더 프레임을 시뮬레이션하는 구조는 아니다. 이 이벤트로 돈·아이템·전투 효과를 지급해서는 안 된다. 개조한 클라이언트가 이미 받은 메시를 표시하거나 복사하는 것까지 막을 수 없다. 공식 서비스 안에서의 소유·이전·다운로드·경제 행위를 통제하는 경계다.

## 신뢰 경계

- Godot는 표시와 입력 장치다. 클라이언트의 소유자 ID, 가격 계산, 재화 잔액, 위치, 시간, 점수, 보상량을 받지 않는다.
- 세션에서 사용자 ID를 결정한다. 모든 개인 물건·모델·생성 작업·생존 기록 접근은 해당 사용자를 조건으로 조회한다.
- 로그인은 Argon2id 비밀번호 해시와 256비트 난수 세션 토큰을 사용한다. DB에는 토큰의 SHA-256 해시만 저장한다. 세션 수명은 12시간이며 로그아웃 시 폐기한다.
- 일반 요청과 로그인 요청에 IP별 한도를 두고, JSON 크기를 스트림 수신 중 8KiB로 제한한다. Pydantic은 미지 필드·범위 밖 숫자·NaN을 거부한다. 오류 응답에 입력값이나 비밀번호를 반사하지 않는다.
- 원격 live 모드는 HTTPS와 초대 코드를 요구한다. demo는 loopback 접속만 허용한다. 실제 운영에서는 프록시·방화벽·계정 관리가 추가로 필요하다.

## 소유권·경제

- SQLite `BEGIN IMMEDIATE` 트랜잭션 안에서 세션, 소유권, 버전, 상태, 잔액을 검사하고 변경한다.
- 구매는 구매자 차감·판매자 지급·소유자 이전·판매 종료가 모두 한 번에 커밋되거나 모두 취소된다.
- 물건 버전은 색칠·배치·회수·거래 때 증가한다. 판매 중인 물건은 배치·수정할 수 없다.
- 요청 UUID와 본문 지문을 저장한다. 같은 UUID의 같은 요청은 저장된 결과를 반환하고, 다른 본문은 거부한다.
- 보상은 완주 상태에서만 지급하며, 지급 여부와 원장 UNIQUE 제약으로 다른 요청 UUID를 사용한 중복 수령도 차단한다.
- 계정당 진행 중인 생존 도전은 하나다. 입력 sequence로 재전송을 거부한다. 실제 서버 시간으로 한 입력당 최대 0.3초만 진행한다. 연결이 없으면 진행이 멈추는 프로토타입 규칙이다.
- 0.5의 달리기 기력·회복·소모, 장애물 충돌, 적의 경로·공격 예고 시점·명중·보상은 서버에서 계산한다. 이동은 최대 0.25 단위로 나누어 지연된 입력으로 나무를 통과하지 못하게 한다. 클라이언트가 보낸 회피 성공·처치·재료 수량은 받지 않는다.
- Esc 일시 정지와 저장 후 마을 귀환은 이 단독 생존 모드의 명시적인 규칙이다. 입력을 멈추면 진행도 멈춘다. 경쟁형 멀티플레이나 오프라인 시간 경과를 검증하는 설계는 아니다. 재접속해도 같은 계정의 도전 하나만 이어간다.
- demo의 환영 재화는 live로 이전되지 않는다. DB에 모드를 기록하여 같은 저장소의 demo/live 전환을 막는다.

## 모델 전달

- 모델은 `server-data/assets` 같은 서버 전용 디렉터리에 둔다. static 경로로 공개하지 않는다.
- `GET /v1/objects/{id}/model`은 현재 소유권을 트랜잭션 내에서 확인한 후 응답한다. 외부 영구 URL/서명 URL을 클라이언트에 주지 않는다.
- Godot는 HTTP 응답 바이트를 GLTFDocument에 전달하며 `user://`에 생성 GLB를 저장하지 않는다. 샘플 의자와 기본 게임 아트는 배포용 자산이므로 프로젝트에 포함된다.
- 마을 클라이언트는 약 3초마다 서버 보관함을 재확인한다. 권한 상실·연결 상실 시 보호된 모델을 비우고 로그인 화면으로 돌아간다.
- 판매 직전 시작되어 이미 승인된 다운로드와 이미 메모리/GPU에 도달한 바이트를 회수할 수는 없다. 악의적 클라이언트의 추출 자체를 막는 DRM은 아니다. 복사한 파일로 서버의 소유권·재화·거래 상태를 변경할 수 없어야 한다.
- 생성 모델은 20MiB, 정적 glTF2 GLB, 제한된 노드/접근자 수만 허용한다. 외부 URI·확장·텍스처·애니메이션·스킨·순환/다중 부모 노드를 거부하고 버퍼 범위·정점 좌표·인덱스를 검사한다. 텍스처 없는 Tripo 설정에 맞춘 의도적으로 좁은 형식이다.
- 파일 검증은 엔진의 모든 파서 취약점을 없애지 않는다. 엔진 업데이트, 별도 검증 프로세스와 실행 자원 제한을 운영 단계에서 추가해야 한다.

## Tripo 비용과 장애

- API 키는 서버 환경변수 또는 `TRIPO_API_KEY_FILE`이 가리키는 서버 전용 파일에서만 읽는다. 클라이언트/리포지터리/오류 응답/로그에 보내지 않는다. 서로 다른 두 키 소스를 함께 지정하면 거부한다. 휴대용 demo 서버는 키를 읽지 않는다.
- paid 플래그, 전역 일일 요청 수, 잔액 확인, 전역 동시 작업 하나를 적용한다. 기본 잔액 기준 200은 설정값이며 실제 요금 보장값이 아니다.
- 제출 전에 `submitting`을 DB에 기록한다. 제출 응답을 잃거나 제출 중 재시작하면 `unknown`으로 잠근다. 자동 재제출하지 않는다.
- task ID가 있으면 일시적인 조회·다운로드 장애에서 같은 task ID만 재조회한다. 명확한 실패는 게임 재화를 한 번 환불한다. 이 환불은 Tripo 자체 환불을 의미하지 않는다.
- unknown 작업은 운영자가 공급자 내역을 확인해 `tools/reconcile_job.py`로 정합성을 복구한다. 기존 task 연결은 조회 성공 후 처리하고 새 제출을 하지 않는다. 미제출 환불은 운영자가 근거를 확인한 경우에만 허용하며 기록된 task가 있으면 거부한다. 변경 전 백업, 감사 기록, 원장 중복 방지와 트랜잭션을 적용한다. 웹 관리자 API/UI는 없다.
- 모델 URL은 HTTPS의 tripo3d.ai 하위 도메인만 허용하며 리디렉션을 따라가지 않는다. 자산 다운로드에는 API 키 헤더를 붙이지 않는다. 실제 공급자 CDN이 달라지면 확인 후 허용 목록을 수정해야 한다.

## 검증과 남은 작업

`tools/backup_server.py`는 실행 중인 SQLite를 backup API로 일관되게 복사하고, 그 스냅샷이 참조하는 불변 GLB만 포함한다. DB/파일 SHA-256과 SQLite integrity/외래키를 검사한다. 백업에는 비밀번호 해시 등 개인 데이터가 포함되므로 운영자 전용 저장소에서 관리한다. 해시 검증은 손상 탐지이며 외부 공격자가 전체 백업과 manifest를 바꾸는 경우의 인증 서명은 아니다.

복원은 기존 디렉터리를 덮어쓰지 않으며 demo/live 모드를 확인한다. 과거 로그인 세션을 모두 폐기하고 진행 중 생성 작업을 unknown으로 잠근다. 백업 이후 공급자에서 발생한 과금을 알 수 없으므로 자동 재제출/환불하지 않는다. 재화·소유권 원장은 복원 당시 스냅샷을 기준으로 되돌아간다. 백업 이후 거래와 공급자 기록 대조는 운영자 책임이다.

서버 테스트는 타 사용자 접근·버전 충돌·세션 폐기/만료·요청 재사용·동시 구매·잔액 부족·보상 재수령·실시간 이동 제한·전체 7일 생존·Tripo 401/HTML400/통신 장애/단일 제출·개인 GLB 전달을 검사한다. Godot 통합 테스트는 실제 HTTP 서버를 별도 포트와 별도 DB로 실행한다.

공개 배포 전에는 호스팅과 TLS, 비밀 저장소, 백업/복구, 중앙 속도 제한, 계정 복구·차단, 재화 지급 정책, 생성 콘텐츠 검수, 모니터링, 침투 테스트가 필요하다. SQLite 단일 프로세스 구성은 작은 시연 규모를 전제로 한다. 멀티 인스턴스로 그대로 확대하면 안 된다.

## 0.6 외형·지역·난이도

`/v1/profile`은 현재 세션의 사용자에게만 저장한다. owner ID, 파일 경로, 능력치 입력은 받지 않는다. 캐릭터/모자/피부는 허용 목록, 머리·상의·하의·신발은 6자리 hex 색만 받는다. 버전 충돌과 request_id 재사용을 기존 원자적 mutation 처리로 검사한다. 공용 시작 캐릭터 외형이며 개인 생성물 소유권과 혼동하지 않는다.

`/v1/runs`는 허용된 map_id/difficulty만 받는다. 이미 활성 도전이 있으면 같은 도전을 반환한다. 생존 시간·이동·피해·자원·보상 배율은 서버가 소유하며 입력 중 난이도나 배율을 변경할 수 없다. 지형의 원형 장애물은 이동과 시야 검사에 같이 반영한다. 보상은 Decimal 계산 후 내림하여 100×1.15가 부동소수점 오차로 114가 되는 문제를 방지한다. 기존 숲 도전은 forest/standard로 읽고 기존 확정 보상은 바꾸지 않는다.
# 0.7 마을 생활 추가

생활 변이는 별도 `homesteads` 계정 행에만 적용하며 소유자를 요청에서 받지 않는다. 서버 성장/입질/재생 시간, 버전 충돌, request_id 재사용, 원자적 재료 차감·결과 저장을 적용한다. 잎전은 유료 생성용 별씨와 교환할 수 없다. 마을의 보행/근접 UI는 로컬이며, 이 구현은 원격 API 호출자가 실제 현장에 서 있는지 검증하지 않는다. 인증된 자동 플레이 방지나 공개 멀티플레이 이동 검증이 완성된 것으로 보아서는 안 된다.

## 0.8.1 방 단위 용량과 생성 프로그램 공개 검사

방당 30개 제한과 별도로 부품 GLB 합계 128MiB, 정점 150만, draw call 512, 텍스처 픽셀 6400만을 제한한다. 서버가 해시를 확인한 불변 파일을 측정·캐시하며 클라이언트의 자체 신고 수치는 받지 않는다. 같은 방 이동은 기존 물건을 중복 계산하지 않고, 회수하면 용량을 반환한다. 집/공방/마을과 계정별로 분리하고 구형 배치 API에도 적용한다. 압축 파일 크기나 픽셀 수는 정확한 VRAM 측정이 아니며 모든 PC의 프레임률을 보장하지 않는다.

생성된 숫자 함수·이벤트는 60초 누적 상태, 124회 클릭, 접근·이탈, 3600/86400/100000초 입력 경계를 공개 전에 검사한다. 시간 입력을 건너뛰는 검사는 그 시간 전체의 상태 누적을 실행한 것이 아니다. 실패 시 이벤트·순서·허용된 오류 코드만 설계 수정에 전달하고 최대 1회 수정한다. 모든 가능한 입력의 의미·시각적 정확성을 증명하지 않으며 런타임 연산량·수치·호스트 명령 제한과 원자적 롤백을 계속 적용한다. 과거 모델 실험의 짧은 검사 점수는 덮어쓰지 않고 새 기준의 검사 결과를 따로 기록한다.

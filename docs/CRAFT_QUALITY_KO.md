# 물건 제작 품질표 (학교 서버 기준)

Tripo가 색까지 입히는 고품질 제작("HD")을 기본으로 쓴다고 보고 정리했습니다. 크레딧은 서버 계산식(`server/studio_pricing.py`, 2026-10-02 공식 요금·실측) 그대로입니다. 학교 서버의 1회 한도는 **30크레딧**, 전체 예산은 **4,000크레딧**입니다.

## 품질 등급

| 등급 | 조합 | 크레딧 | 한도 30에서 | 기대할 수 있는 결과물 |
|---|---|---|---|---|
| S | P2 + 색 입힘 | 110 | ✗ (한도 110 이상 필요) | 형태 정확도와 색 품질이 가장 좋을 것으로 기대합니다. 다만 부품당 면 3,000개 제한 때문에 기본 모델과의 차이가 줄어듭니다. 같은 문장으로 비교해 보고 정하는 걸 권합니다 |
| **A** | 사진 참고 + 색 입힘 | **30** | ✓ | 원하는 모양과 색을 가장 잘 재현합니다. **한도 안에서 최고 품질**입니다 |
| A− | 사진 다듬기 + 색 입힘 | 35 | ✗ (35 필요) | 배경이 있거나 복잡한 사진도 물건만 깔끔하게 뽑습니다 |
| **B+** | 글로 설명 + 색 입힘 | **20** | ✓ | 나뭇결, 무늬, 그림 같은 색 세부가 들어갑니다. 모양은 AI가 문장을 해석한 결과라 생각과 다를 수 있습니다. **들인 크레딧에 비해 효과가 가장 좋습니다** |
| B | 움직이는 가구 2부품 + 색 입힘 | 40 | ✗ (40 필요) | 문이나 뚜껑이 움직이고 색도 입혀집니다. 부품 이음새가 어색할 수 있습니다 |
| C+ | 움직이는 가구 2~3부품 + 직접 색칠 | 20~30 | ✓ | 움직임은 생기지만, 색은 게임에서 단색으로 칠합니다 |
| C | 사진 참고 + 직접 색칠 | 20 | ✓ | 모양은 사진에 가깝고, 색은 단색입니다 |
| D | 글로 설명 + 직접 색칠 | 10 | ✓ | 모양만 나옵니다. 장난감·로우폴리 느낌입니다(심사 서버의 체험판 제작) |

- 모든 제작은 **부품당 면 3,000개**로 요청합니다. P2를 써도 아주 섬세한 형태는 단순해집니다.
- 움직이는 가구는 **부품 수 × 단가**입니다. 부품이 여러 개면 사진은 직접 쓰이지 않고 AI 설명으로 바뀝니다(사진 다듬기 제외).
- 한도를 40으로 올리면 B, 110으로 올리면 S가 열립니다. 서버 명령의 `--max-credits` 숫자만 바꾸면 됩니다.

## 게임 안에서의 부담 (0.11.0부터)

색 입힌 Tripo 모델에는 2048×2048 텍스처가 3장(색, 노멀, ORM) 들어 있습니다. 0.11.0부터 게임이 불러올 때 **1024로 줄이고, 가능하면 압축**합니다.

| | 텍스처 메모리 (물건 1개) | 불러오는 시간 |
|---|---|---|
| 줄이기 전 (원본 2K × 3장) | 약 38MB(원본 픽셀) → 밉맵 포함 약 50MB | 해석 때문에 잠깐 끊김 |
| **줄인 뒤 (1K, 압축)** | **약 5.6MB** (편집기에서 측정, 약 1/7) | 약 0.1초 (게임 시작 때 한 번 압축 준비 약 1초) |
| 줄인 뒤 (1K, 압축 기능이 없는 빌드일 때) | 약 12MB (추정, 약 1/4) | 약 0.1초 |
| 직접 색칠 모델 | 거의 0 | 거의 0 |

- 폴리곤은 어느 옵션이든 부품당 3,000면이라 부담이 거의 없습니다.
- 모델 종류(P2냐 기본 모델이냐)는 게임 부담과 상관없습니다. 차이는 Tripo 크레딧입니다.
- 배포판 실행 파일에서 압축 기능을 쓸 수 있는지는 아직 확인하지 못했습니다. 못 쓰는 경우에도 1K로 줄이기는 항상 적용되어 메모리는 약 1/4이 됩니다.

## 추천
- 학교 기본: **B+ (글 + 색 입힘, 20)**. 원하는 모양이 분명할 때는 **A (사진 + 색 입힘, 30)**.
- 예산 4,000으로 B+만 쓰면 약 200번, A만 쓰면 약 133번 만들 수 있습니다.
- P2는 발표·전시용으로 몇 개만 만들 때 한도를 잠깐 올려 쓰는 것을 권합니다.

# 텃밭 서버 API

`GET /v1/homestead`, `POST /v1/homestead`를 그대로 사용한다. 인증된 계정의 마을만 읽고 수정하며 소유자 ID를 받지 않는다. N4 클라이언트는 아래 서버 상태로 성장 단계와 수확 버튼을 표시한다.

## 성장과 물주기

- 단계는 `seed → sprout → growing → ripe`다. 서버 시계로 계산하며 접속 종료 중에도 자란다. 단계 경계에 도달하면 즉시 다음 단계가 된다.
- 미급수 속도는 0.5, 급수 속도는 1이다. 물주기 전까지 얻은 성장량은 유지한다. 비는 없으며 `catalog.weather`는 `none`이다.
- 물은 **계정에 고정된 시간대의 다음 자정까지** 유효하다. 자정부터 다시 0.5 속도가 되고, 다시 물을 줄 수 있다. 요청의 시간대 헤더를 바꿔도 계정의 날짜 경계는 바뀌지 않는다.
- 물주기는 심어진 작물에 적용한다. 수확하면 급수 상태도 없어진다. 새로 심은 작물에는 다시 물을 줄 수 있다. 익은 작물은 물 없이도 수확할 수 있다.
- 폴링은 저장 버전을 바꾸지 않는다. `create_app(clock=...)`의 서버 시계를 주입해 테스트하며 클라이언트의 시각/성장량 입력은 받지 않는다.

## 응답 필드

상위 `version`은 변이마다 1 증가하고 `server_time`은 Unix 초다. `plots` 배열의 인덱스가 요청의 `plot`이다. 빈 밭은 기존처럼 `{ "x": -20.2, "z": -33.0 }`만 가진다.

| 심어진 밭의 필드 | 의미 |
| --- | --- |
| `x`, `z` | 마을 지도 좌표(m) |
| `crop` | 작물 ID |
| `planted_at` | 심은 서버 시각(Unix 초) |
| `stage`, `stage_index` | 단계 문자열 및 0~3 인덱스 |
| `progress` | 전체 성장 비율 0~1 |
| `growth_seconds` | 누적 유효 성장 초, 작물의 `seconds`가 상한 |
| `growth_updated_at` | 이 응답에서 성장량을 계산한 기준 시각. 서버 저장용 체크포인트이며 클라이언트가 보내지 않음 |
| `watered` | 현재 급수 효과가 유효한지 |
| `watered_at` | 마지막 급수 시각. 미급수/일부 구형 저장에는 없을 수 있음 |
| `watered_until` | 급수 만료 시각. 미급수이면 `null` |
| `growth_rate` | 현재 유효 성장 초/실제 초(0.5 또는 1) |
| `ready` | 수확 가능 여부. `stage == "ripe"`와 같음 |
| `remaining` | 추가 급수가 없을 때 수확까지 남은 실제 초. 자정 만료를 포함하며 미급수여도 숫자 |
| `ready_at` | `server_time + remaining`. 익은 작물에서는 현재 서버 시각이며 과거 성숙 시각을 뜻하지 않음 |

각 `catalog.crops[crop]`는 기존 `name`, `seconds`, `yield`, `seed_cost`, `price`와 새 `stage_seconds`를 제공한다. `seconds`는 유효 성장 총량이며 `stage_seconds`는 `seed`, `sprout`, `growing`의 개별 소요량이다. 클라이언트는 단계 순서를 `catalog.growth_stages`에서 읽고, 재조회 후 서버 값을 기준으로 화면을 갱신한다.

| 작물 ID | 씨앗/새싹/성장 초 | 총 유효 초 | 씨앗 가격 | 수확량 | 개당 판매가 |
| --- | --- | --- | --- | --- | --- |
| turnip | 20 / 30 / 40 | 90 | 2 | 2 | 3 |
| carrot | 25 / 40 / 55 | 120 | 3 | 2 | 4 |
| pumpkin | 30 / 50 / 70 | 150 | 4 | 2 | 6 |
| strawberry | 40 / 60 / 100 | 200 | 5 | 3 | 4 |
| sunflower | 50 / 90 / 120 | 260 | 6 | 1 | 15 |
| radish (무, 신규) | 20 / 35 / 45 | 100 | 2 | 2 | 3 |
| potato (감자, 신규) | 30 / 45 / 65 | 140 | 3 | 2 | 4 |
| tomato (토마토, 신규) | 35 / 65 / 80 | 180 | 5 | 3 | 4 |
| corn (옥수수, 신규) | 50 / 80 / 110 | 240 | 6 | 2 | 7 |

기존 작물의 총 유효 초·가격·수확량은 그대로다. 새 씨앗은 기존 `catalog.shop`의 `<crop>_seed` 항목으로 판매한다. 기존 잎전 구매/판매, 판매 수입 3잎전당 별씨 1개, 기본 일일 별씨 상한 15개는 변경하지 않았다. 잎전은 `economy.change_coins`, 별씨는 기존 `economy.change_shards`를 거친다.

## 요청과 검증

```json
{
  "request_id": "eb00738e-ce7b-43f0-81e2-46ec939e6132",
  "version": 7,
  "action": "plant",
  "plot": 0,
  "item": "tomato"
}
```

| action | 추가 입력 | 결과/조건 |
| --- | --- | --- |
| `till` | `x`, `z` | 밭 추가. 구역·격자·허수아비 예약 칸·겹침·18칸 상한 검사 |
| `plant` | `plot`, `item`(작물 ID) | 빈 밭에 씨앗 1개 소비 |
| `water` | `plot` | 심어진 밭에 자정까지 급수. 이미 유효하면 거절 |
| `harvest` | `plot` | 익은 작물만 수확. 가방/누적 수확량을 갱신하고 밭을 비움 |
| `untill` | `plot` | 추가한 빈 밭 삭제. 최초 6칸은 삭제 불가 |
| `buy` | `item`(`<crop>_seed`), `quantity`(1~20) | 기존 씨앗 가게 구매 |
| `sell` | `item`(작물 ID), `quantity`(1~20) | 기존 판매/별씨 일일 상한 적용 |

`catalog.farm_zones`는 `[x0,z0,x1,z1]` 목록이며 현재 `[[-24.5,-40.5,-15.5,-29.0]]`다. `farm_grid`는 1.8m, `farm_grid_origin`은 `[-22,-33]`이며 이 원점 칸은 예약되어 있다. 저장된 밭을 수정할 때도 구역·격자·예약 칸을 검사한다. 다른 계정의 밭을 지정하는 API는 없다. 실제 플레이어의 보행 위치/접근 거리는 검증하지 않는다.

요청 한 건에는 작업 한 개만 들어간다. 같은 계정에서 성공한 `request_id`와 동일한 본문을 재전송하면 **최초 응답 전체**를 돌려주고 다시 실행하지 않는다. 다른 작업/밭/버전으로 같은 ID를 재사용하면 `409 request_id_reused`다. 성공 응답은 오래된 상태일 수 있으므로 최신 상태는 GET으로 읽는다. 실패한 요청은 기록하지 않으며, 사용자에게 새로운 작업을 시킬 때는 새 UUID를 사용한다.

동시 요청은 DB 트랜잭션과 버전 비교로 직렬화된다. 동일 버전으로 서로 다른 ID의 수확 두 건을 보내면 한 건만 성공한다. 동일 ID의 동시 재전송은 두 응답이 같고 수확물은 한 번만 지급한다. `untill` 후에는 뒤쪽 인덱스가 이동하므로 응답의 `plots`와 `version`을 함께 교체해야 한다.

주요 `409 detail`: `stale_life_version`, `request_id_reused`, `life_no_plot`, `life_not_farmland`, `life_plot_limit`, `life_plot_overlap`, `life_plot_occupied`, `life_empty_plot`, `life_already_watered`, `life_not_ready`, `life_starter_plot`, `life_invalid_crop`, `life_missing_items`. 잘못된 필드/음수 인덱스/시간 주입은 `422`, 미인증은 `401`이다.

## 기존 저장 변환

좌표 없는 6칸은 기존 시작 좌표를 사용한다. `growth_seconds`가 없는 작물만 이전 형식으로 판단한다. 미급수 작물은 원래 `planted_at`부터 0.5 속도로 계산하므로 오래된 작물은 즉시 익을 수 있다.

이미 급수한 구형 작물은 약속된 `ready_at`을 보존한다. **구형 작물에 한해서** 그 마감이 자정 뒤라면 급수 효과를 해당 마감까지 연장한다. 이후 새로 심는 작물은 모두 새 자정 규칙을 따른다. 변환은 조회 시에도 같은 결과를 내며, 해당 밭의 성공적인 변경 작업에서 저장된다. 기존 가방·재화·수확 기록은 유지한다.

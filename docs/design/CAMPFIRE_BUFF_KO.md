# 모닥불을 생존자 버프로 전환하는 서버 설계

이 변경은 모닥불을 몬스터를 막는 결계에서 생존자의 회복과 전투를 돕는 장소로 바꾸는 선택 기능이다. **기본값은 기존 동작인 `barrier`이며, 아래 수치 승인 전에는 `buff`를 활성화하거나 배포하지 않는다.** 서버 구현과 클라이언트 표시 계약만 추가하며, 클라이언트와 소셜 presence 코드는 변경하지 않는다.

구현 기준은 [campfire.py](../../server/campfire.py), [simulation.py](../../server/simulation.py), [coop.py](../../server/coop.py), [survival_maps.py](../../server/survival_maps.py)다. 환경변수 검증은 [config.py](../../server/config.py)의 `Settings.validate()`에서 수행한다.

## 1. 모드와 저장 호환성

| 설정 | 동작 |
| --- | --- |
| 환경변수 미설정 | `barrier` |
| `TRIPOTHON_CAMPFIRE_MODE=barrier` | 현재의 몬스터 퇴치 동작 유지 |
| `TRIPOTHON_CAMPFIRE_MODE=buff` | 신규 탐험에서 생존자 버프와 구조 기능 사용 |
| 그 외 값 | 설정 검증 실패; 조용히 다른 모드로 대체하지 않음 |

설정값은 앞뒤 공백을 제거하고 소문자로 비교한다. 솔로 신규 탐험의 `campfire_mode`, 협동 신규 탐험의 `world.campfire_mode`에 선택한 모드를 저장한다. 진행 중인 탐험은 환경변수가 바뀌거나 서버가 재시작되어도 저장한 모드를 따른다. 이 필드가 없는 예전 저장은 항상 `barrier`로 해석한다. 따라서 설정을 `buff`로 바꾸는 것만으로 기존 탐험의 규칙이 바뀌지 않는다.

효과 시간은 서버 탐험의 `elapsed`를 사용한다. 클라이언트 시각이나 클라이언트가 보낸 체력·위치로 효과를 결정하지 않는다. 기존 한 번의 시뮬레이션 진행 상한인 0.3초를 유지하므로 접속하지 않은 시간을 회복·구조 진행으로 적립하지 않는다.

## 2. 현재 동작: `barrier`

중앙 모닥불의 좌표는 `(0, 0)`이다. `fire_until > elapsed`이고 생존자의 중앙까지 거리가 **4 미만**이면 `warm=true`다. 반경 경계 4는 효과 밖이다.

- 밤에 대상 생존자가 따뜻한 범위 안에 있으면 몬스터는 공격 대신 `warded` 상태로 전환한다. 중앙에서 4.8 미만에 있으면 밖으로 물러나고, 5.2보다 멀면 반경 5 부근으로 접근하며, 그 사이에서는 주변을 돈다. 불 자체의 충돌벽이 아니라 대상의 `warm` 여부에 따른 몬스터 AI 분기다. 협동에서는 각 몬스터가 선택한 대상 생존자를 기준으로 한다.
- 불의 범위에서는 밤 추위 피해가 발생하지 않는다. 별도의 추위 중첩이나 체온 상태는 없다.
- 모닥불에 의한 체력·기력 추가 회복, 범위 이탈 후 공격 버프, 동료 구조는 없다. 협동에서 쓰러진 플레이어는 동료가 생존하는 동안 관전한다.
- 중앙까지 거리 3 이하에서 목재 2개를 사용하면 연소 시간이 30초 늘어난다. 남은 시간이 60초를 초과하면 추가 연료 투입을 거절하고, 연장 후 남은 시간은 최대 90초다. 이 비용과 시간은 두 모드에서 동일하다.

맵의 `CAMP_CLEAR=4.5`는 일반 자원의 자동 배치를 피하는 공터 크기이며, 버프나 몬스터 퇴치 반경이 아니다. 중앙 화덕의 반경 1.05 충돌, 벤치·장작·텐트 등의 실제 장애물, 자원과 지형 충돌은 두 모드 모두 유지된다. `buff`에서도 몬스터는 이런 물리적 장애물을 우회한다.

## 3. 새 동작: `buff`

불이 켜진 범위 안에서도 몬스터가 추적하고 공격한다. `warded` 분기를 사용하지 않으며, 불 주변의 생존자는 공격을 피하거나 동료와 함께 싸워야 한다.

살아 있고 탐험이 진행 중인 생존자는 낮과 밤 모두 범위 안에서 체력·기력을 회복한다. 밤 추위 피해도 기존처럼 막는다. 추위는 누적 상태가 없으므로 여기서의 추위 제거는 매 틱의 밤 추위 피해를 억제한다는 뜻이다. 굶주림 피해, 잿불 지형 피해, 빙판 이동 감속과 추가 허기, 몬스터 공격 피해는 계속 적용된다.

불 안에서 `warmed`를 갱신하며, 불 밖으로 나가거나 불이 꺼진 뒤에도 마지막 갱신부터 최대 5초 동안 공격력이 10% 증가한다. 이동 전에도 온기를 기록하므로 다른 동료가 불을 피운 직후나 불 안에서 구조된 직후에 바로 이동하더라도 잔열을 유지한다. 이동 속도 보너스는 없다. 이 잔열은 불 밖의 회복이나 추위 면역을 연장하지 않는다. 체력 0인 생존자는 회복으로 자동 부활하지 않는다.

### 수치 제안과 기존 능력치 비교

| 항목 / `campfire.py` 상수 | 값 | 적용 의미 |
| --- | --- | --- |
| `RADIUS` | 4.0 | 불이 켜져 있고 중앙까지 거리 `< 4.0`일 때 적용 |
| `HP_PER_SECOND` | 초당 0.6 HP | 최대 HP 100; 연속 30초 체류 시 최대 18 HP 회복 |
| `STAMINA_PER_SECOND` | 초당 4 기력 추가 | 최대 기력 100; 기존 일반 회복 14에 더해 초당 18, 달리기 소모 22와 합치면 초당 18 소모 |
| 추위 면역 | 범위 안에서 밤 추위 피해 0 | 범위 밖 기본 피해는 초당 `0.28 × 맵 cold × 난이도 cold` |
| `WARMED_SECONDS` | 5초 | 범위 안에서 갱신; 마지막 갱신 이후 남는 공격 효과 |
| `WARMED_ATTACK_MULTIPLIER` | 1.10배 | 맨손 10 → 11, 창 25 → 27.5; 공격 재사용 대기 0.7초 유지 |
| `REVIVE_SECONDS` | 진행량 8초 | 유효한 조력자 한 명 기준 범위 밖 구조에 8초 필요 |
| `REVIVE_FIRE_MULTIPLIER` | 2배 | 쓰러진 동료와 조력자 모두 켜진 불 안이면 구조에 4초 필요 |
| `REVIVE_RADIUS` | 2.3 | 조력자와 쓰러진 동료 사이 거리 `≤ 2.3` |
| `REVIVE_HP` | 30 HP | 구조 완료 시 회복하는 체력; 허기·기력을 초기화하지 않음 |
| `NIGHT_RECOVERY_MULTIPLIER` | 1.5배 | 아래 밤 전투 완화 조건에서 몬스터 공격 후 회복 시간을 연장 |

HP 18/30초는 붕대 한 개의 즉시 회복 30 HP보다 낮다. 불에 머무르면 서서히 회복하지만 공격과 굶주림을 버틸 무적 영역은 되지 않는다. 기력 추가 회복도 달리기의 순소모를 없애지는 않는다. 수치는 승인 대상으로 제시하며, 실제 난이도 평가는 각 맵과 난이도에서 별도로 수행한다.

### 협동 자동 구조

기존 협동에는 구조 동작이 없으므로 `buff`에만 자동 근접 구조를 추가한다. 별도 `revive` 입력은 없다. 살아 있는 동료가 쓰러진 플레이어 가까이 멈춰 서면 구조를 시작한다.

유효한 조력자는 철수하지 않았고 HP가 0보다 크며, 마지막 협동 입력 이후 10초 미만인 플레이어다. 쓰러진 플레이어도 철수하지 않았고 마지막 입력 이후 10초 미만이어야 한다. 두 사람의 거리가 2.3 이하이고 기존 `clear_swing`의 장애물 통과 판정을 만족해야 한다. 벽이나 장애물 너머에서 구조할 수 없다.

정지 여부는 서버가 수락한 이동 의도로 판단한다. 유효기간 0.6초 안의 이동 입력 벡터가 0이 아니면 조력자로 인정하지 않는다. 유효기간이 지난 이동 입력은 정지로 취급한다. 공격이나 제작 입력 자체가 구조를 중단하는 별도 조건은 없다.

조건을 만족하는 조력자 중 가장 높은 배율 하나만 적용한다. 두 사람이 불 안이면 2배, 그 외에는 1배이며 여러 조력자의 속도는 합산하지 않는다. 유효한 조력자가 없어지면 진행량을 0으로 되돌린다. 불이 꺼지거나 유효한 조력자 구성이 달라져 1배와 2배 사이에서 배율만 바뀌는 경우에는 쌓인 진행량을 유지한다. 완료 시 HP를 30으로 설정하고 구조 진행·달리기·이동 의도를 초기화한다.

솔로 패배, 협동 전원 쓰러짐, 탐험 종료 뒤에는 구조하지 않는다. 전원 접속이 끊겨 시간 진행이 멈춘 경우에도 만료된 접속 조건을 반영하여 구조 진행을 초기화한다. 쓰러진 클라이언트도 협동 `/input`의 정상적인 순번 증가와 무이동 입력을 계속 보내야 10초 연결 조건을 유지할 수 있다. GET 조회만으로 `last_seen`을 갱신하지 않는다.

## 4. 밤 난이도 조절 지점

`campfire.recovery_seconds()`는 밤의 몬스터 전투 루프에서 일반 공격 또는 돌진이 끝나고 `recover`에 들어갈 때 호출한다. **그 시점의 대상 생존자가 `buff` 모드의 켜진 불 안에 있을 때** 기본 회복 시간을 `NIGHT_RECOVERY_MULTIPLIER=1.5`배로 늘린다. 협동에서는 공격 대상으로 정한 플레이어의 위치를 사용한다.

| 구간 | 기존 / 불 밖 | 불 안의 `buff` 대상 |
| --- | --- | --- |
| 일반 근접·포자 공격 후 회복 | 0.85초 | 1.275초 |
| 돌진 종료 후 회복 | 해당 몬스터의 `stun` 값 | 해당 값 × 1.5; 기본값 1.4초이면 2.1초 |
| 생존자의 공격 적중으로 생기는 경직 | 0.4초 | 0.4초 유지 |

이 설정은 전체 공격 간격을 일괄 1.5배로 만드는 것이 아니라 공격 후 회복 구간만 연장한다. 공격 예고 시간, 이동 속도, 피해량, 출현 개수·위치·주기와 보스 편성은 그대로다. 공격이 빗나갔어도 회복 구간에는 같은 판정을 적용한다. 범위 밖의 `warmed`만 남은 상태에는 이 완화를 적용하지 않는다.

조정할 때는 `NIGHT_RECOVERY_MULTIPLIER`를 1.0으로 두면 이 완화를 끌 수 있다. 회복량, 잔열 시간·공격 배율, 구조 시간·배율은 위 상수로 각각 조절한다. 범위는 두 모드가 공유하므로 `RADIUS` 변경 시 기존 `barrier`의 범위도 달라진다는 점을 함께 검토해야 한다. 별도 환경변수로 노출한 수치 설정은 없으며, 운영자가 바꿀 수 있는 모드 환경변수와 코드의 밸런스 상수를 구분한다.

## 5. 클라이언트 계약

기존 탐험 응답에 필드를 추가한다. [multiplayer.py](../../server/multiplayer.py)의 소셜 presence·프로필·파티 통신 형식은 수정하지 않는다.

- 솔로: `GET /v1/runs/{run_id}`, `POST /v1/runs/{run_id}/input`의 탐험 상태.
- 협동: `GET /v1/coop/runs/{run_id}`, `POST /v1/coop/runs/{run_id}/input`의 탐험 상태.
- 생성 응답은 기존처럼 탐험 `id`를 반환한다. 상태 조회나 입력 응답에서 효과 필드를 읽는다.
- 협동 응답의 최상위 생존자 필드는 요청한 본인에 대한 값이다. `players[]`에는 동료별 `warm`, `buffs`, `revive`가 추가된다. `campfire`는 최상위에서 공유한다.

### 공용 모닥불과 생존자 필드

| 필드 | 형식 / 의미 |
| --- | --- |
| `campfire.mode` | `"barrier"` 또는 `"buff"`; 구저장에도 항상 계산하여 제공 |
| `campfire.x`, `campfire.z` | 중앙 좌표, 현재 모두 `0.0` |
| `campfire.radius` | 효과 반경, 현재 `4.0` |
| `campfire.remaining` | 남은 연소 시간, 초, 최솟값 0 |
| `campfire.active` | `remaining > 0` |
| `campfire.blocks_monsters` | `barrier`이면 `true`, `buff`이면 `false`; 모드의 규칙을 표현하므로 실제 활성 표시는 `active`도 확인 |
| `fire_remaining` | 기존 필드 유지; `campfire.remaining`과 같은 값 |
| `warm` | 기존 의미 유지: 켜진 불의 반경 안인지 여부. 생존·철수 상태와 별도로 계산하므로 이 값만으로 버프 아이콘을 켜지 않음 |
| `buffs` | 현재 생존자에게 적용되는 버프 목록; 효과 없으면 `[]` |
| `revive` | 구조 상태 객체 또는 `null` |

신규 저장에는 최상위 `campfire_mode`도 존재할 수 있지만, 구저장에는 없을 수 있으므로 클라이언트의 모드 판정에는 항상 `campfire.mode`를 사용한다. 서버 내부의 `warmed_until`, `revive_progress`, `revive_rate`는 응답에서 숨기고 아래의 상대 시간·비율로 전달한다.

| `buffs[]` 종류 | 추가 필드 | 표시 |
| --- | --- | --- |
| `id="campfire_regeneration"` | `remaining`, `hp_per_second=0.6`, `stamina_per_second=4.0`, `cold_immune=true` | 불 안 회복·추위 면역 아이콘. `remaining`은 현재 연료의 남은 시간이며, 범위를 벗어나면 즉시 제거 |
| `id="warmed"` | `remaining`, `attack_multiplier=1.1` | 공격력 +10% 잔열 아이콘. 불 안에서는 남은 시간 5초로 유지, 이탈 후 감소 |

`barrier`에서는 `warm`이 참이어도 `buffs=[]`이고 `revive=null`이다. 종료 상태, 체력 0, 철수 상태에는 생존자 버프를 표시하지 않는다. 구조 객체는 진행 중인 `buff` 협동에서 철수하지 않은 쓰러진 플레이어에 대해 표시한다.

| `revive` 필드 | 의미 |
| --- | --- |
| `progress` | 완료까지 쌓인 진행량을 0~1로 정규화한 값 |
| `active` | 현재 유효한 조력자가 있으면 `true` |
| `remaining` | 현재 속도 유지 시 완료까지 남은 시뮬레이션 초; 조력자가 없으면 `null` |
| `speed_multiplier` | 조력자 없음 `0`, 일반 구조 `1`, 두 사람 모두 불 안 `2` |

불 안에서 살아 있는 생존자의 응답 예시:

```json
{
  "campfire": {
    "mode": "buff", "x": 0.0, "z": 0.0, "radius": 4.0,
    "remaining": 17.0, "active": true, "blocks_monsters": false
  },
  "fire_remaining": 17.0,
  "warm": true,
  "buffs": [
    {"id": "campfire_regeneration", "remaining": 17.0,
     "hp_per_second": 0.6, "stamina_per_second": 4.0, "cold_immune": true},
    {"id": "warmed", "remaining": 5.0, "attack_multiplier": 1.1}
  ],
  "revive": null

```

협동에서 두 사람이 불 안에 있고 구조 진행량이 절반일 때 쓰러진 플레이어의 `revive`는 `{"progress": 0.5, "active": true, "remaining": 2.0, "speed_multiplier": 2.0}`이다.

클라이언트는 켜진 불의 좌표·반경으로 범위 원을 표시하고, `buff`에서는 회복 영역이라는 안내와 몬스터 진입 가능 안내를 제공해야 한다. 구조 가능한 동료에게 접근하여 정지하라는 안내, 진행 막대, 배율과 남은 시간을 표시한다. 기존 `barrier` 안내는 해당 모드에서 유지한다. 아이콘과 수치에는 서버의 `buffs`를 사용한다. 범위를 벗어나면 회복·추위 면역 아이콘을 제거하되 잔열 아이콘은 서버가 보내는 남은 시간 동안 유지한다. 응답에서 효과가 사라지면 해당 아이콘도 제거한다. 표시를 부드럽게 보간할 수는 있지만 회복·피해·구조 결과를 클라이언트가 확정하지 않는다. 알 수 없는 버프 ID는 무시하고, 새 필드가 없는 구버전 서버에는 기존 표시로 대응한다.

## 6. 검증 범위

두 모드에서 불의 지속 시간과 경계, 기존 추위 억제와 물리 충돌을 확인한다. `barrier`의 퇴치·기존 공격력·추가 회복 없음·구조 없음과, `buff`의 몬스터 진입·회복 상한·잔열 만료·공격 배율·야간 회복 구간 연장을 각각 확인한다. 협동은 개인별 범위, 구조의 거리·장애물·정지·접속·철수 조건, 8초/4초 완료, 조력자 중복 비가산, 전멸 종료, 응답의 본인·동료 필드 일치를 검증한다. 구저장과 진행 중 저장의 모드 유지도 회귀 검증 대상이다.

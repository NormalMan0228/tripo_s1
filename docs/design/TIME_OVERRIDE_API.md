# 데모·테스터 계정의 시간대 재정의 API

이 API는 로그인한 계정의 **화면 표시 시간**을 영구 저장한다. 서버에서 부여한
`users.is_tester=1` 테스터 또는 `users.role='admin'` 운영자만 사용할 수 있다.
계정 이름, 클라이언트의 역할 표시, 데모 서버 접속만으로 권한을 얻지 못한다.
일반 계정은 조회와 변경 모두 `403 time_override_forbidden`을 받는다.

## 조회

`GET /v1/dev/time_override`

`Authorization: Bearer <token>`이 필요하다. 마을 입장, presence 등록·갱신과
무관하게 로그인 직후 조회할 수 있다. 자신의 계정 설정만 반환한다.

```json
{"time_override":"night","hour":22,"updated":1792141200.0}
```

- `time_override`: 저장된 프리셋 이름, 0~23 정수, 또는 `null`.
- `hour`: 클라이언트가 적용할 0~23 정수 시각. 설정이 없으면 `null`.
- `updated`: 마지막 변경의 Unix 시각(초). 설정이 없으면 `null`.

## 설정·해제

`POST /v1/dev/time_override`

프리셋을 지정한다.

```json
{"time_override":"morning"}
```

| 프리셋 | 적용 시각 |
| --- | --- |
| `morning` | 08:00 |
| `noon` | 12:00 |
| `evening` | 18:00 |
| `night` | 22:00 |

직접 시각을 지정하려면 0~23 정수를 보낸다.

```json
{"time_override":17}
```

기본 시간으로 돌아가려면 명시적으로 `null`을 보낸다.

```json
{"time_override":null}
```

설정·해제 응답은 GET과 같은 형식이다. 해제 후에는 세 필드가 모두 `null`이다.
같은 값을 다시 설정하거나 해제를 반복하면 같은 결과가 유지되며 변경 기록도
중복 생성되지 않는다. `request_id`는 받지 않는다. 이후 다른 값으로 변경한 뒤
예전 설정 요청을 다시 보내면 그 값을 새로 설정하므로 클라이언트는 변경 요청을
순서대로 보내야 한다.

빈 객체, 누락 필드, 추가 필드, 다른 프리셋, 문자열 숫자, 소수, 참/거짓,
범위를 벗어난 시각은 `422 invalid_request`이다. 미로그인은 `401 login_required`,
유효하지 않거나 만료된 토큰은 `401 session_expired`이다.

## 클라이언트 적용

1. 로그인·재연결 후 GET을 호출한다. 계정을 바꿀 때 이전 계정의 재정의 캐시를 지운다.
2. `hour`가 있으면 해당 시각으로 하늘, 태양, 조명 등 로컬 표시를 고정한다.
   시간이 흘러도 자동으로 증가시키지 않는다. 프리셋 이름을 클라이언트에서 다시
   환산하지 말고 응답의 `hour`를 사용한다.
3. 설정 UI에서 POST 응답을 받은 즉시 적용한다. `null`이면 기존 시간대·현실 시각
   계산으로 돌아간다. 다른 기기의 변경을 반영하려면 설정 화면을 열거나 재접속할 때
   GET을 다시 호출한다. presence 응답에는 이 설정이 포함되지 않는다.
4. `403`이면 조절 UI를 숨기고 로컬 재정의를 해제한다. 서버는 매 요청마다 권한을
   확인하므로 테스터 권한 회수도 다음 조회에 반영된다.

설정은 계정별 SQLite 저장소에 보존되어 로그아웃·서버 재시작 이후에도 유지된다.
다른 플레이어, 방문한 마을의 호스트, 공유 월드의 시각을 변경하지 않는다.
일일 제한·초기화, 낚시 조건, 퀘스트 보상, 생일 이벤트 등의 서버 판정에는 기존 실제
시간이 계속 쓰인다. 이 API의 시각을 UTC 오프셋이나 게임 판정 시계에 덮어쓰지 않는다.
